# Challenge Library & Clone — Phase 1 Design

**Goal:** Allow Django admins to mark challenges as templates, organise them by category, and clone them into any org's data silo via a Django admin action.

**Architecture:** A global `ChallengeCategory` model (outside the org silo) plus three new fields on `RouteChallenge`, a standalone clone service, and an enhanced Django admin with an intermediate clone action. Phase 2 (teacher self-serve library UI) calls the same service via a REST endpoint — no backend changes needed at that point.

**Tech Stack:** Django, Django admin, PostgreSQL. No frontend changes in this phase.

---

## Data Model

### New: `ChallengeCategory` (`challenges/models.py`)

Global reference data — derives from `models.Model`, **not** `BaseOrgModel`. Org-scoped models may FK to it without breaking the silo guarantee; it never FKs back into org-scoped data.

```python
class ChallengeCategory(models.Model):
    name         = models.CharField(max_length=100, unique=True)
    slug         = models.SlugField(unique=True)
    description  = models.TextField(blank=True)
    default_icon = models.CharField(max_length=20, blank=True)
    # ^ emoji or short icon name copied into challenge_icon at challenge
    #   creation time. e.g. "🏛️" for Urban History, "🌿" for Nature.
    #   For Language Learning challenges the flag emoji is copied from
    #   SupportedLanguage / OrgManagedLanguage instead.

    class Meta:
        ordering = ['name']
        verbose_name_plural = 'challenge categories'

    def __str__(self):
        return self.name
```

Seed categories at launch (via a data migration or the admin): `Language Learning`, `Nature & Ecology`, `Urban History`, `STEM`, `Art & Architecture`.

### Changes to `RouteChallenge`

Five new fields:

```python
is_template      = models.BooleanField(default=False)
category         = models.ForeignKey(
    'ChallengeCategory',
    null=True, blank=True,
    on_delete=models.SET_NULL,
    related_name='challenges',
)
author_name      = models.CharField(max_length=200, blank=True)
content_language = models.CharField(max_length=10, default='en')
challenge_icon   = models.CharField(max_length=20, blank=True)
```

`is_template=False` on all existing rows (safe default — nothing appears in the library until an admin explicitly flags it). All other new fields are nullable/blank so existing challenges need no immediate update.

**`content_language`** — the language the challenge text and descriptions are written in (e.g. `"en"`). Allows future filtering by audience language, independent of what the challenge teaches.

**`challenge_icon`** — a denormalized emoji or icon identifier copied at challenge creation time from the authoritative source:
- Language Learning challenges: copied from `SupportedLanguage.flag_emoji` or `OrgManagedLanguage`'s equivalent. This means indigenous/minority languages with no Google `SupportedLanguage` entry (e.g. Mi'kmaq) work without any FK constraint — the org's `OrgManagedLanguage` provides the icon, which is then copied in.
- All other categories: copied from `ChallengeCategory.default_icon` (e.g. `"🏛️"` for Urban History).

The icon is intentionally frozen at creation time. If an org later wants to update it, they edit the challenge directly — a trivial admin field change.

**`author_name`** is the public display name shown in the library ("by María García" or "by Innsbruck Language School"). Payment identity is resolved via the existing `created_by` FK to the User model — no separate author email field needed.

### Migrations

Two migration files:

1. `0001_add_challenge_category.py` — creates the `ChallengeCategory` table (including `default_icon`).
2. `0002_routechallenge_new_fields.py` — adds `is_template`, `category`, `author_name`, `content_language`, and `challenge_icon` to `RouteChallenge`. Depends on migration 1.

## Clone Service (`challenges/services.py`)

Standalone function — no admin or API logic inside it. Both Phase 1 (admin action) and Phase 2 (REST endpoint) call it identically.

```python
from django.db import transaction
from .models import RouteChallenge, ChallengeStop, Activity

@transaction.atomic
def clone_challenge(source: RouteChallenge, target_org, cloned_by) -> RouteChallenge:
    """
    Deep-copies source into target_org.
    - poi is nulled on each stop (cross-org POI access not supported yet)
    - Clone starts as DRAFT with is_template=False
    - join_code is auto-generated by RouteChallenge.save()
    """
    new_challenge = RouteChallenge(
        owning_org=target_org,
        created_by=cloned_by,
        title=f"Copy of {source.title}",
        description=source.description,
        language=source.language,
        level=source.level,
        ux_mode=source.ux_mode,
        category=source.category,
        author_name=source.author_name,
        content_language=source.content_language,
        challenge_icon=source.challenge_icon,
        status=RouteChallenge.DRAFT,
        is_template=False,
    )
    new_challenge.save()  # triggers join_code generation

    for stop in source.stops.order_by('order'):
        new_stop = ChallengeStop(
            owning_org=target_org,
            challenge=new_challenge,
            order=stop.order,
            name=stop.name,
            lat=stop.lat,
            lng=stop.lng,
            radius_m=stop.radius_m,
            poi=None,  # nulled — cross-org POI copy is out of scope
        )
        new_stop.save()

        for activity in stop.activities.order_by('order'):
            Activity(
                owning_org=target_org,
                stop=new_stop,
                order=activity.order,
                activity_type=activity.activity_type,
                content=activity.content,  # JSONField — value copy, no references
                unlock_condition=activity.unlock_condition,
            ).save()

    return new_challenge
```

**Error handling:** `@transaction.atomic` ensures that any failure at any level (stop or activity creation) rolls back the entire clone. The caller receives the exception and is responsible for surfacing it to the user.

## Django Admin

### `ChallengeCategoryAdmin`

```python
@admin.register(ChallengeCategory)
class ChallengeCategoryAdmin(admin.ModelAdmin):
    list_display        = ['name', 'slug', 'description']
    prepopulated_fields = {'slug': ('name',)}
    search_fields       = ['name']
```

### Updated `RouteChallengeAdmin`

Add to `list_display`: `is_template`, `category`, `challenge_icon`, `content_language`
Add to `list_filter`: `is_template`, `category`, `status`, `language`, `content_language`
Add `is_template`, `category`, `challenge_icon`, and `content_language` to the editable fieldset.

### `clone_to_org` Admin Action (two-step)

Step 1 — admin selects one or more challenges in the list view and chooses "Clone to org" from the actions dropdown.

Step 2 — Django serves an intermediate confirmation page (`admin/challenges/clone_to_org.html`) with:
- A summary of the selected challenges (title, category, stop count)
- A `<select>` populated with all `OwningOrg` instances, ordered by `org_domain_name`
- Confirm / Cancel buttons

Step 3 — on confirmation, the view calls `clone_challenge(challenge, target_org, request.user)` for each selected challenge and renders a success page listing:
- Each new challenge's title and ID
- The target org
- A link to the new challenge in the admin

The intermediate view lives in `challenges/admin_views.py` and is wired into the admin URL config. It checks `request.user.is_staff` before rendering.

## What Phase 2 Adds (separate spec)

Phase 2 is entirely additive — no changes to models, migrations, or the clone service.

| Addition | Detail |
|---|---|
| `GET /api/challenges/templates/` | Returns published `is_template=True` challenges, readable cross-org, filterable by `category__slug` and `content_language`. Response includes `challenge_icon` for library card display. |
| `POST /api/challenges/<id>/clone/` | Calls `clone_challenge(source, request.user.owning_org, request.user)`, returns new challenge |
| Teacher library page | Browse templates by category, preview stop count and activities, one-click clone |

## Out of Scope (this phase)

- POI deep copy on clone — `poi` is nulled; revisit when route/challenge integration is built
- Per-org category customisation — no `OrgManagedChallengeCategory` bridge needed yet
- Category CRUD via API — categories managed in the Django admin only
- Bulk category seeding migration — seed manually via admin at launch
