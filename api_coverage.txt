NOTABLE FINDINGS THIS PASS:

0. [ADDED 2026-09-16, post-audit, CORRECTED same day after discussion with John] Media storage tier (MediaFileWrapper.is_public: public bucket + permanent URL, vs. private bucket + signed time-limited URL) and object visibility (Map.is_public / Poi permissions: who can even load the object via the API) are two separate, independent concepts - don't conflate them. Verified the code links them nowhere today: MediaFileWrapper.is_public (media_pipeline/models/media_file.py:60) comes purely from a client-supplied upload-time flag (MediaUploadSerializer default True, media_pipeline/api/serializers.py:59-60), with no path anywhere deriving it from the owning Map/POI's own is_public. Every real client either hardcodes is_public=true (map_builder/lib/upload.ts:89) or omits the field and gets the True default (strollopia-sites, data_logger, strollopia-pwa, and content/views_dl.py:432's base64 path) - so all media currently lands in the public bucket regardless of map visibility. THIS IS NOT A LIVE BUG: the API is in a pilot with every map public today, so current behavior is fully consistent with actual policy - and "private map, but media in the public bucket" (security through obscurity - the URL is only ever handed out via an already permission-gated API response) is a legitimate, cheaper design choice, not automatically wrong. It's a real decision still to make before private maps/POIs are a near-term feature. Full design-space writeup: strollopia-api/docs/superpowers/plans/2026-09-16-media-privacy-policy.md (planning only, nothing to implement yet). See also the updated /api/media/signed-download-url row.
